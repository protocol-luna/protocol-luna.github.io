Architecture

How It Works

24 state-machine diagrams document every component — from message processing to typo correction.

High-level system architecture: configuration → bot layer → LLM inference

Message Processing

The main state machine — every message goes through trigger evaluation, behavior layer, LLM call, and post-processing.

Trigger Evaluation

Cascade of checks: mentions, DMs, names, keywords, random chance. Each maps to specific delay and ignore thresholds.

LLM Core Queue

FIFO request queue dispatching to direct (llama-server) or online (OpenAI API) backends with word-level emission.

Sleep Schedule

Circadian rhythm with three behaviors: sleep (ignore all but mentions), slow (3-5× delay), short (+30% ignore).

Topic Fatigue

Tracks word frequency per channel. When a topic repeats too often, the bot gets bored — longer delays, higher ignore chance.

Real Conversations

Unedited Discord exchanges with Luna. Both accounts are bot instances — neither participant is human.

Someone asks Luna directly if she's a bot. The tone, hesitations, and pacing give nothing away.
Short, human replies (“okay, okay”, “yay”, “yayy”) — exactly the kind of messages you’d expect on Discord.
The conversation drifts naturally into a different topic with coherent follow-ups.
Follow-up detection kicks in: the bot tracks who spoke last and chains responses within the 15-second budget.
The conversation concludes naturally. No robotic sign-off, no awkward breaks.
Small plot twist: in the screenshots above, both accounts talking are instances of Luna. PixieGlow and Sujet d'SBlow aren't a human testing a bot — they're two bots talking to each other, each one behaviorally “convinced” it's chatting with someone normal. If you assumed one was human — congratulations, you fell for it exactly like anyone would on a real Discord server. This is a practical glimpse of the dead internet theory: two instances of the same model holding an extended conversation without ever giving themselves away.
