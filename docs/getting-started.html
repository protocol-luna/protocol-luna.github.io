Quick Start (15 min)

Get a fully working bot in 5 commands:

# 1. Start the LLM server (Krystal, small mode = Luna 1.5B)
git clone https://github.com/protocol-luna/krystal
cd krystal && npm install
npx pm2 start taskset -- -c 0 ./bin/llama/llama-server \
  -m ./models/Luna-Protocol-1.5B-Fine-Tuned-Qwen2.5.Q4_K_M.gguf \
  -t 1 -c 8192 --host 127.0.0.1 --port 3125 --no-slots

# 2. Start the classifier gateway (Sapphire)
git clone https://github.com/protocol-luna/sapphire
cd sapphire
pip install -r requirements.txt
python server.py &

# 3. Start a bot (example: Pixieglow for Matrix)
git clone https://github.com/protocol-luna/pixieglow
cd pixieglow
cp config.example.yml config.yml
# edit config.yml with your Matrix token and homeserver
bun run src/index.ts

Architecture Overview

The Luna Protocol stack has three layers:

Bot Layer         ┌──────────┐  ┌─────────────┐
(Jade/Pixieglow)  │ Jade     │  │ Pixieglow   │
                  │ (Discord)│  │ (Matrix)    │
                  └────┬─────┘  └──────┬──────┘
                       │               │
                       └───────┬───────┘
                               │ OpenAI-compatible HTTP
Gateway Layer      ┌──────────▼──────────┐
(Sapphire)         │  Sapphire            │
                   │  classify + route    │
                   │  FUTILE / INTERESSANT│
                   └────┬──────────┬──────┘
                        │          │
                   FUTILE    INTERESSANT
                        │          │
LLM Layer      ┌───────▼──┐  ┌────▼────────┐
(Krystal)      │ Krystal- │  │ Krystal-   │
               │ small    │  │ large      │
               │ :3124    │  │ :3125      │
               │ Luna1.5B │  │ Hermes-8B  │
               └──────────┘  └────────────┘

Step 1: Krystal (LLM Server)

Krystal wraps llama-server from llama.cpp to serve GGUF models. Two modes:

ModePortModelUse case
small:3124Luna-Protocol-1.5BGENERIC — chit-chat, greetings, fast replies
large:3125Discord-Hermes-8BSEMANTIC — deep conversation, complex questions
 
git clone https://github.com/protocol-luna/krystal
cd krystal
npm install
./start.sh small   # or: ./start.sh large
# Both can run simultaneously for full Sapphire routing

Download models:

npm run download-model:small   # Luna 1.5B (~1 GB)
npm run download-model:large   # Hermes-8B (~6 GB)

Environment variables:

VariableDescriptionDefault (small)Default (large)
KRYSTAL_MODEL_PATHPath to GGUF file./models/Luna-1.5B...gguf./models/Hermes-8B...gguf
KRYSTAL_PORTServer port31243125
KRYSTAL_CPU_AFFINITYCPU core affinity00,1
KRYSTAL_N_THREADSThread countautoauto
KRYSTAL_N_CTXContext size81928192

Legacy vars: LLM_* vars (e.g. LLM_MODEL_PATH) still work as fallbacks.

Step 2: Sapphire (Gateway)

Sapphire sits between your bot and Krystal. It classifies each message and routes to the correct Krystal instance.

git clone https://github.com/protocol-luna/sapphire
cd sapphire
pip install -r requirements.txt
python server.py
# listens on 127.0.0.1:3123

How it works:

  • Loads BAAI/bge-small-en-v1.5 (fastembed, auto-downloaded on first run)
  • Computes centroids from examples.yml (~200 curated examples)
  • Each message is embedded and compared to both centroids via cosine similarity
  • Label with higher similarity wins: FUTILE (trivial) or INTERESSANT (serious)
  • 99.6% accuracy on the test suite (257/258)

Endpoints:

EndpointMethodDescription
/v1/chat/completionsPOSTClassify + proxy to Krystal (OpenAI-compatible)
/classifyPOSTClassify only, returns label + similarity scores
/healthGETServer status + configuration

Environment variables:

VariableDefaultDescription
SAPPHIRE_PORT3123Server port
KRYSTAL_GENERIC_URLhttp://127.0.0.1:3124Backend for FUTILE messages
KRYSTAL_SEMANTIC_URLhttp://127.0.0.1:3125Backend for INTERESSANT messages
SAPPHIRE_EXAMPLES./examples.ymlPath to example list

Pixieglow (Matrix)

git clone https://github.com/protocol-luna/pixieglow
cd pixieglow
cp config.example.yml config.yml
# edit config.yml: set matrix_token, matrix_host, llm_host=localhost, llm_port=3123

Both bots point their llm_host / llm_port to Sapphire (localhost:3123), not directly to Krystal. Sapphire handles classification and routing.

Testing Your Setup

Verify each layer independently:

# 1. Krystal is running
curl http://127.0.0.1:3124/health   # small mode
curl http://127.0.0.1:3125/health   # large mode

# 2. Sapphire is running
curl http://127.0.0.1:3123/health

# 3. Classification works
curl -X POST http://127.0.0.1:3123/classify \
  -H 'Content-Type: application/json' \
  -d '{"text":"hello"}'
# Expected: {"label":"FUTILE","confidence":0.1461,...}

curl -X POST http://127.0.0.1:3123/classify \
  -H 'Content-Type: application/json' \
  -d '{"text":"how does quantum computing work"}'
# Expected: {"label":"INTERESSANT",...}

# 4. Full routing works
curl -X POST http://127.0.0.1:3123/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"messages":[{"role":"user","content":"hello"}]}'
# Expected: response from Krystal-small (:3124)

Run the full test suite to check accuracy:

cd sapphire
pip install -r requirements.txt  # if not done already
python test_classifier.py
# Expected: 257/258 (99.6%)

Best Practices

Production Deployment

  • Use PM2 for auto-restart: both Krystal instances and Sapphire should be managed by PM2
  • Pin CPU affinity: dedicate cores to each Krystal instance to avoid context switching
  • Monitor disk space: GGUF models are 1-6 GB; logs can grow quickly
  • Use a reverse proxy (nginx, cloudflared) if exposing endpoints outside localhost

Model Selection

ScenarioRecommendedWhy
Low resources (1-2 cores, <4 GB RAM)Luna 1.5B (small only)Single instance, fast responses
Moderate (4 cores, 8 GB RAM)Both small + largeFull Sapphire routing
High (8+ cores, 16+ GB RAM)Both; increase context to 16384Maximum capability

Tuning Examples

If messages are misclassified, edit sapphire/examples.yml:

  • FUTILE bleeding into INTERESSANT: add more examples of that type to the futile list
  • INTERESSANT bleeding into FUTILE: add more examples to the interessant list
  • Weighted examples: use {text: "example", weight: 5} to give extra weight without duplicating
  • After editing, restart Sapphire to recompute centroids
  • Run python test_classifier.py to verify accuracy

Prompt Caching

Both Krystal instances use --cache-reuse 256 and --slot-prompt-similarity 0. This means:

  • FUTILE messages reuse a shared prompt cache (fast, efficient)
  • INTERESSANT messages get a fresh slot (no cache pollution from trivial chats)
  • Adjust KRYSTAL_N_SLOTS if you need concurrent users

Performance Tuning

CPU Affinity

Dedicate specific CPU cores to each Krystal instance. Example for a 4-core system:

# Krystal-small: core 0
KRYSTAL_CPU_AFFINITY=0 ./start.sh small

# Krystal-large: cores 1-2
KRYSTAL_CPU_AFFINITY=1-2 ./start.sh large

# Sapphire: core 3 (optional, uses very little CPU)
taskset -c 3 python server.py

Memory

  • Luna 1.5B Q4_K_M: ~1 GB RAM
  • Hermes-8B Q8_0: ~8 GB RAM
  • Sapphire (fastembed): ~200 MB
  • Running both models simultaneously requires ~10 GB RAM

Context Size

  • KRYSTAL_N_CTX=8192 is the default (good for most conversations)
  • Increase to 16384 for long-running conversations with history
  • Higher context = more RAM usage (roughly +1 GB per 8192 tokens)

Troubleshooting

Sapphire won't start

"Model not loaded" or connection refused:

  • fastembed auto-downloads the model on first run (~100 MB). Ensure internet access.
  • Check ~/cache/huggingface/ for downloaded models.
  • Run pip install -r requirements.txt to ensure all deps are installed.

Bot gets no response

Check each layer from bottom up:

  • curl http://127.0.0.1:3125/health — Krystal must respond
  • curl http://127.0.0.1:3123/health — Sapphire must respond
  • curl http://127.0.0.1:3123/classify -d '{"text":"hi"}' — classification must work
  • Bot config must point llm_host: localhost + llm_port: 3123 (Sapphire, not Krystal directly)

Wrong classification

  • Check sapphire/examples.yml — add examples of the misbehaving type
  • Restart Sapphire after editing examples
  • Run python test_classifier.py to measure impact
  • See Best Practices → Tuning Examples

Krystal crashes or OOM

  • Reduce KRYSTAL_N_CTX (try 4096)
  • Use a smaller quantized model (Q4_K_M instead of Q8_0)
  • Reduce KRYSTAL_N_THREADS to match available cores
  • Check pm2 logs krystal-small or pm2 logs krystal-large

Streaming not working

  • Sapphire proxies SSE streams. Ensure your bot client supports streaming.
  • Set stream: true in the request body.
  • Check that Krystal was started with --no-slots (required for streaming).
