Luna Protocol v2 -- Emerald era
The architecture was reorganized in July 2026: a new brain service (Emerald) now sits between bots and Sapphire. Bots are thin WebSocket clients with no direct Sapphire or LLM logic.

  • Fine-tuned Qwen2.5 1.5B model, trained on 200k samples from Discord-Dialogues
  • Quantized GGUF format (Q4_K_M, 941 MB)
  • Few-shot priming: Sapphire injects example conversations before the system prompt
  • Architecture: Platform → Bot (WebSocket) → Emerald (brain) → Sapphire (HTTP) → Krystal (llama.cpp)
  • All behavior and LLM logic lives in Emerald + Sapphire; bots are adapters only

Emerald (Brain)

Emerald is the central decision engine. It runs a WebSocket server on port 3126 that platform adapters (Jade, Pixieglow) connect to.

How it works

  1. Bots connect via WebSocket and forward MessageEvents (with optional debug: true)
  2. Emerald evaluates behavior rules: burst cooldown, sleep schedule, typo/swap probability, ignore prefixes
  3. For non-empty messages, Emerald calls Sapphire's /v1/respond HTTP API with the message and behavior context
  4. When debug is set, Emerald passes "debug": true to Sapphire
  5. Emerald receives the response text and optional debug stats
  6. Emerald applies typo/swap behavior to the response text
  7. Emerald sends a RespondCommand back to the bot with responseText and optional debugStats

Key files

  • src/server.ts — WebSocket server (connection management, event routing, command dispatch)
  • src/brain.ts — Decision engine: evaluates behavior, calls Sapphire, applies typo/swap
  • src/sapphire-client.ts — HTTP client to Sapphire with snake_case to camelCase mapping
  • src/protocol.ts — WebSocket message types (events, commands, debug stats)
  • src/behavior/*.ts — Burst, sleep, typo, mannerisms
  • src/state/*.ts — State management, triggers, topic fatigue

Sapphire (LLM Gateway)

Sapphire is a Python FastAPI server on port 3123. Emerald is its only client.

Capabilities

  • Classification: Message embedding via fastembed + BAAI/bge-small-en-v1.5. Centroid similarity labels each message by conversation category.
  • Emotion scoring: Four centroids (positive, negative, high_arousal, low_arousal) compute valence and arousal on a [-1, 1] scale. State per conversation decays via EMA.
  • Session management: Per-channel conversation history with configurable max messages and TTL.
  • Few-shot injection: Category-matched example conversations injected server-side before the system prompt.
  • Emotion-aware sampling: Temperature, repeat penalty, and mirostat entropy dynamically adjusted by valence/arousal.
  • Degenerate detection: Regex-based detection of loops, stutters, and empty replies with automatic retry.
  • Debug mode: Returns token counts, timing, emotion state, and classification confidence when requested.
  • Single-backend: All messages forward to one Krystal instance on :3124.

Endpoint: POST /v1/respond

Bots (Jade / Pixieglow)

Both bots are thin WebSocket clients of Emerald. They have no Sapphire or LLM logic.

Jade (Discord)

  • TypeScript + Eris library
  • Connects to Emerald via WebSocket on connect and on reconnect
  • Listens to Discord messages, forwards as MessageEvents
  • -debug prefix in message content enables per-message debug mode
  • Responds to RespondCommand by posting responseText to Discord
  • In debug mode, appends -# formatted stats lines (token counts, timing, emotion, confidence)
  • Optional Piper TTS for voice messages
  • Config: discord_token, emerald_host, emerald_port, TTS paths

Pixieglow (Matrix)

  • TypeScript + Bun + Matrix client-server API
  • Connects to Emerald via WebSocket
  • Sync loop polls Matrix API for new messages, forwards to Emerald
  • Responds to RespondCommand by posting responseText to Matrix rooms
  • Config: matrix.homeserver_url, matrix.access_token, emerald_host, emerald_port

Behavior System

All behaviors are evaluated by Emerald before calling Sapphire and applied after receiving the response. The bot itself has no behavior logic.

Burst

When engaged in an active conversation, Emerald allows faster follow-ups (2-6s delay) for up to 2 messages, then a 60s cooldown. Prevents the bot from dominating a thread.

Sleep Schedule

ModeEffect
sleepOnly mentions pass through; all other messages ignored
slowResponse delay multiplied by 3-5x
shortIgnore chance increased by 30%

Typos / Letter-Swap

Applied to the response text after receiving it from Sapphire. Configurable probability (default 8%) of replacing a letter with an adjacent key (AZERTY layout). Swap chance (default 12%) for transposing adjacent letters.

Mannerisms

Configurable chance (default 7.5%) of injecting mannerism patterns into the response.

Ignore Prefixes

Messages starting with configured prefixes (e.g. !) are ignored by Emerald and not forwarded to Sapphire.

Debug Mode

Debug mode flows through the entire stack:

  1. Bot level: Message starts with -debug prefix → sets debug: true on the MessageEvent
  2. Emerald: Passes debug: true to Sapphire's /v1/respond
  3. Sapphire: Returns debug_prompt_tokens, debug_completion_tokens, debug_time_ms, debug_tokens_per_second, debug_emotion_state_valence, debug_emotion_state_arousal, debug_classification_confidence
  4. Emerald: Maps snake_case → camelCase into DebugStats object, included in RespondCommand
  5. Bot: Appends -# formatted lines to the Discord/Matrix response

Example debug output on Discord:

Hey, how are you?
-# 12 tokens | 450 in | 3.2s | 3.75 t/s | emo: +0.6v/0.3a | conf: 0.85

Emotion-Aware Sampling

Sapphire dynamically adjusts Krystal's sampling parameters based on the classified emotional state of the conversation:

ParameterFormulaEffect
Temperatureclamp(0.7 + arousal × 0.3, 0.4, 1.0)Higher arousal = more randomness
Repeat penaltyclamp(1.15 - valence × 0.1, 1.0, 1.3)Higher valence (positive) = less penalty
Mirostat entropyclamp(6.0 + arousal × 2.0, 3.0, 8.0)Higher arousal = more entropy

This replaces prompt-based mood injection. For a 1.5B model, adjusting sampling parameters is more reliable than injecting mood descriptions into the system prompt.
